## 앱으로 쓰기 (11/06~, 이쪽을 쓴다)
바탕화면·시작 메뉴 **동영상 번역기** (검은 창 없이 `.venv\Scripts\pythonw.exe app.py`, 아이콘 `ui/brand/app.ico` = 메이커 마크) → 작은 창이 뜬다 → 영상 켜고 **읽기 시작**. 이미 떠 있을 때 또 누르면 창만 하나 더 뜬다(앱이 두 개 돌지 않게).
말 빠르기·음량·목소리·자동 빨라지기·토막 거르기를 창에서 바로 바꾼다. 창을 닫으면 몇 초 뒤 알아서 끝난다.

구조: `app.py`(PC 안에서만 도는 작은 서버, 127.0.0.1:8765) + `ui/index.html`(화면) + `reader_core.py`(읽기 엔진).
`ui/index.html`을 그냥 더블클릭하면 "앱 연결 끊김"만 뜬다 — 화면일 뿐이고 파이썬(app.py)이 떠 있어야 한다.
검은 창(`자막읽어주기_시작.bat`)과 앱을 **동시에 켜지 말 것** — 둘 다 읽어서 목소리가 겹친다.

## 검은 창으로 쓰기 (예전 방식)
1. 바탕화면 **LiveCaptions Translator** 바로가기 → 번역기 켜기 (홈 화면에 두기). 시작 메뉴 검색으로 켜면 바로 꺼진다.
2. 바탕화면 **자막 읽어주기** 바로가기 → 검은 창이 뜨고 대기
3. 강의 영상 재생 → Heami가 한국어로 읽음
4. 멈출 때: 검은 창에서 Ctrl+C → "일괄 작업을 끝내시겠습니까?"에 Y. 기록은 `logs/`에 CSV로 남는다.

`자막읽어주기_시작.bat`은 **CP949**로 저장돼 있다(UTF-8로 저장하면 cmd에서 한글 줄이 깨져 명령이 안 된다). 고칠 땐 인코딩 유지.
점검만: `자막읽어주기_시작.bat --check`

## exe 로 쓰기·나눠 주기 (11/06)
- 만들기: `.venv\Scripts\python.exe build_exe.py` → `dist\VideoTranslator\VideoTranslator.exe` (49MB 폴더) + `dist\VideoTranslator.zip` (25MB). 바탕화면·시작 메뉴 바로가기가 이 exe 를 가리킨다.
- 앱 창 = WebView2 (pywebview). 제목줄·작업 표시줄 아이콘 = 메이커 마크. pywebview 가 없으면 예전 Edge 앱 모드로 대신 뜬다.
- exe 일 때 설정·기록은 `%LOCALAPPDATA%\VideoTranslator` (paths.py: RES=읽기용, DATA=쓰기용). 폴더에서 `app.py` 로 돌리면 예전처럼 이 폴더.
- **준비 점검** 카드(⚙): 실시간 자막 / Ollama(없으면 winget 설치·꺼져 있으면 켜기) / 번역 모델(없으면 받기, 진행률) / 그래픽카드(VRAM 으로 속도 안내). 모자란 게 있으면 켤 때 자동으로 열린다.
- exe 안에 안 들어가는 것: Ollama 와 모델(약 5GB) — 점검 카드가 받아 준다.
- 회사 백신(Trend Micro Apex One)이 이 PC에서 exe 실행은 막지 않았다(11/06).
- 11/08 집 PC(윈도우 10 Enterprise 19045, RTX 4080)에서 clone → `py -3.14` venv → 빌드 32초, exe 실행·준비 점검 확인. **윈도우 10엔 실시간 자막이 없어서 말 번역은 안 되고 화면 번역만 된다.** 윈10에서 말 번역까지 하려면 PC 소리를 직접 받아 Whisper 로 받아쓰는 쪽으로 '귀'를 바꿔야 한다.

## 실험 기록
- 11/06 2단계 첫 실행에서 자막 창에 `An young Kirang Ijebuto.`가 찍혀 있었다. 1단계에서 Heami가 말한 "안녕, 희랑. 이제부터"를 실시간 자막이 **영어로 받아쓴 것**. → 예상한 "되먹임" 문제가 실제로 있다. 4단계에서 Heami가 말하는 동안 들어온 자막은 버려야 한다.

- 11/06 강의 영상(Introduction: Zendesk for Customer Service)을 틀고 40초 읽음. 영어 인식은 잘 된다("Agents often waste time navigating disconnected tools", "Knowledge builder, Action builder, App builder").
  - 자막은 **단어 하나씩 늘어나고**, 문장이 끝나면 마침표가 붙는다. 앞 문장도 나중에 고쳐진다(`tools we saw that` → `tools. We saw that`).
  - 그래서 "마침표로 끝난 문장 **뒤에 새 문장이 시작되면**, 앞 문장은 확정"으로 보고 그때 번역하면 된다.
  - 한 덩어리가 길어지면 자막 칸이 새 줄로 넘어간다(`No.` 로 새로 시작).

- 11/06 3단계 수정: 번역기 기록 카드(Log Cards)가 꺼져 있으면 기록 칸(…CaptionLog)이 갱신되지 않는다. → 현재 문장 칸(OriginalCaption / TranslatedCaption)을 읽고, 영어 앞부분이 바뀌면 앞 문장을 확정하는 방식(`SentenceFinalizer`)으로 바꿈.
- 11/06 4단계 첫 성공: 90초 동안 11문장 읽음, 건너뜀 0. 강의 영어 인식은 Heami가 말하는 중에도 깨끗했다(되먹임 쓰레기 문장 안 보임). 남은 문제:
  - 문장 경계가 겹쳐서 같은 내용을 두 번 읽는다("You gain the visibility…"가 짧은 판, 긴 판 두 번).
  - 덜 끝난 문장의 번역이 잘린다("따라서 AI 기반 자체에서 시작됩니다").
  - 지연이 0.0초로 찍힘 → 확정 시점부터 잰 것. 문장이 들리기 시작한 때부터 재야 한다.

- 11/06 중복 거르기: 확정 문장을 4초(HOLD) 들고 있다가, 뒤에 온 문장들이 단어 70%(DUP_COVER) 이상 덮으면 짧은 판으로 보고 버림. 1차 실측 13문장 읽음·6개 버림.
- 11/06 엇갈림 수정: 한국어 칸이 영어 칸보다 늦게 바뀌어서 새 영어 문장에 앞 문장 번역이 붙었다("OK nothing in the chat" → 물 마시는 문장 번역, 긴 문장 → "내장."). 새 문장이 시작되면 앞 문장 번역과 같은 값은 받지 않게 함(`stale`).
- 11/06 수정 후 실측: 90초 10문장 읽음·2개 버림·밀림 0. 영어-한국어 짝 맞음. 지연(문장이 처음 보인 때 → 말 시작) 7~18초, 평균 약 10초. 앞뒤 문장이 일부 겹쳐 두 번 들리는 구간이 아직 조금 있다(QA tools 문장).

- 11/06 지연 줄이기: 마침표+0.8초 안정이면 먼저 확정, HOLD 4→3초, 이미 읽은 내용 70% 겹치면 건너뜀, 늦을수록 빨리(225→최대 300).
  - 실측(90초): 16문장 읽음(전 10), 지연 4~12초 평균 약 7초(전 약 10초). 대기(확정→말 시작)는 거의 HOLD 3초 그대로 → 지금 병목은 '확정까지'(2~8.5초)와 HOLD.
  - 대가: 토막 문장이 늘었다("매.", "그리고 이건 우리의 싱글이에요."). 번역기가 문장을 겹쳐 끊는 구간은 여전히 일부 반복된다("visibility" 문장 3번).
  - 한계: 문장 끊는 위치를 번역기가 정한다. 더 나아지려면 실시간 자막 원문(마침표가 정확함)으로 우리가 직접 문장을 끊고, 공식 번역 API로 번역해야 한다.
- 11/06 번역기가 켜지자마자 꺼짐: `setting.json`을 '현재 폴더'에 저장하는데 시작 메뉴 검색 등으로 켜면 현재 폴더가 system32라 권한 오류. → 번역기를 `내 문서\LiveCaptionsTranslator`로 옮기고 시작 위치를 지정한 바탕화면 바로가기로만 켠다.

- 11/06 토막 거르기(`fragment_reason`): 영어 4단어 미만 / 한국어 6자 미만 / 영어 1단어당 한국어 0.9자 미만(번역 잘림) / 5자 초과(짝 엇갈림)면 버림. 지난 기록 40문장에 대 보니 "내장.", "그리고 그게 뭔가라는 걸 알잖아", "매." 3개만 걸림. 실측(데모 영상 구간): 11문장 읽음·중복 4·토막 0, 지연 평균 약 8초.

- 11/06 ⚠ **4단계 시험은 전부 소리가 안 났다.** pyttsx3 는 `runAndWait()`를 두 번째 부르면 말하지 않고 0.1초 만에 돌아온다(워밍업 때문에 첫 문장부터 무음). 기록 파일엔 "읽음"으로 남아서 몰랐다. → `HeamiSpeaker`를 윈도우 음성 엔진(SAPI.SpVoice) 직접 호출로 바꿈. 실측: 빠르기 225/260/300 → 4.2/2.0/1.3초 동안 실제로 말함.
  - 그래서 위의 지연 숫자(평균 7~8초)는 **말하는 시간이 0인 상태**에서 잰 것이다. 실제로 말하면 대기가 늘어난다. 다시 재야 한다.
  - 교훈: "기록에 남았다"와 "사람이 들었다"는 다르다. 소리 나는 기능은 사람이 들었는지 꼭 물어본다.

- 11/06 "안 읽는 글이 너무 많아": 소리 켜고 처음 돌린 기록 58줄 중 18줄 버림(중복 9, 토막 9). 중복 9개 중 절반은 **짧은 판을 먼저 읽은 뒤 긴 판이 와서 통째로 버린 것** → 긴 판에 새로 붙은 문장("질문 있으신 분 있나요?")이 사라졌다. → `new_korean_part`: 한국어를 문장 단위로 쪼개 이미 읽은 문장만 빼고 새 문장만 읽는다. 토막 거르기 9개는 "능력.", "지진 우리는 항상." 같은 것이라 그대로 둠.

- 11/08 화면 번역 빈칸 버그: 블록 여러 개를 번호 붙여 보내면 EXAONE 이 2번을 1번 아래 들여쓰기로 붙이고 번호를 빼먹음(온도 0.1 이라 매번 같음) → 2번 자리가 빈 채로 캐시에까지 남아 다시 눌러도 빈칸. → 짝 안 맞은 블록만 하나씩 다시 묻고, 빈 번역은 캐시에 안 넣음. 영어 OCR 엔진(en-US)은 AI 를 `A1` 로 읽어서 `clean_ocr`에 `A1/Al → AI` 추가. 시험: 블록 2개 1.4초(다시 묻기 포함), 평소 0.5~1초.

## 어려운 점 (4단계에서 풀 것)
1. 되먹임: 실시간 자막은 PC 소리를 다 들어서 Heami 목소리도 받아쓴다.
2. 밀림: 강사는 계속 말하는데 번역+읽기는 늦다. 빨리 읽기 / 오래된 문장 건너뛰기 / 영상 0.8배.
3. 문장 끊기: 자막은 덜 끝난 문장을 계속 고쳐 쓴다. 언제 한 문장으로 보고 번역할지.
